> **减小 patch 的原理**：当前 256×256 patch 输出一个概率值，覆盖 stride×stride 区域（默认 32×32 像素 ≈ 960m×960m）。
> 减小 patch 到 128×128 或 64×64 后，每个预测覆盖更小的地理范围，空间精度成倍提升。
> 代价是 patch 数量增加（128→4倍，64→16倍），训练和推理时间相应增长。

## 风险预案

| 风险                    | 概率 | 应对                                         |
| --------------------- | -- | ------------------------------------------ |
| 滑坡数据源不明确，无法做分类标签  | 中  | 用现有 GeoTIFF 第 6 波段代替，或手动标注 20 个 patch 作为验证 |
| 小patch导致数据量激增，Colab内存不足 | 中  | 减小batch_size，或先用大patch验证流程，小patch留到AutoDL |
| Colab 12GB 内存不够跑 8 通道 | 低  | 提前降采样到 60m 或分块处理                           |
| AutoDL 没抢到 3090 实例    | 低  | 用 T4 替代，batch\_size 降到 4                   |
| 某周进度落后                | 高  | 利用下周一补进度，最多落后 3 天；超过则跳过该周非核心任务             |
| 理论学习遇到瓶颈              | 中  | 先跳过，标记为待补课，不要卡住整体进度；求助 AI 辅助理解             |
| 论文看不懂                 | 中  | 先读中文解读/博客，建立概念后再读原文；善用 AI 翻译辅助             |
| 领域知识过于抽象，难以消化         | 中  | 结合自己研究区的具体案例来理解，多画图，少死记硬背                  |

## 核心原则

1. **三条线并行，阶段驱动**：每个阶段有明确的侧重点和目标，理论学习和领域知识不是代码的附属品，而是同等重要的支柱
2. **学以致用，代码验证**：每学完一个 DL 概念，立刻回看项目代码中对应的实现，加深理解
3. **一次只改一件事**：每次代码改动后跑验证，确认有效再改下一件
4. **断点不通过就停下来修**：不要带病进入下一阶段，宁可慢一周
5. **论文阅读要有产出**：每篇至少写 3 句话笔记 + 1 个对项目的启发，不要只是"看过"
6. **领域知识驱动创新**：滑坡领域知识不是"背景"，而是创新方向的来源——理解消落区的特殊机制，才知道需要什么因子、什么模型
7. **目标导向，产出可见**：每个阶段结束有明确的交付物（笔记、图、报告、模型），不做无目的的探索
