## 风险预案

| 风险                             | 概率 | 应对                                                      |
| ------------------------------ | -- | ------------------------------------------------------- |
| PyG 安装失败（Windows/CUDA 兼容性）       | 中  | 用 Colab 替代本地开发；Colab 默认已装 PyG                              |
| GEE NDVI/降雨导出超时或失败              | 中  | 减小 maxPixels 或分区域导出（上游/下游）；终极方案直接用 SRTM 5 因子 + 水位，先跑通模型 |
| 方案 B 全量 attention OOM (T4 16GB)   | 高  | 用 batch 拆分（256-512 节点/批），已在计划中；或直接升级方案 C                    |
| 方案 C 与方案 B AUC 差距大（Performer 近似损失） | 中  | 增大 Performer 的 `nb_features` 参数；或保留方案 B 作为正式方案，方案 C 作为生产优化      |
| 5 折交叉验证某折 AUC 极低               | 中  | 检查该折样本分布（正样本是否极稀疏），考虑重划折；极端情况降低为 3 折                     |
| Colab T4 被限流或断连                  | 中  | 保存 checkpoint 中间结果；连接中断时从最近 checkpoint 恢复训练                  |
| XGBoost 基线 AUC < 0.70            | 低  | 检查特征提取是否有误（如特征值大量 NaN、时序未截断导致泄漏），重新提取特征后重试               |
| 学习进度落后（某个理论模块看不懂）              | 高  | 用 AI 辅助理解，简化到最核心概念（不求 100% 精通，先求能复现）；标记为"后续补课"，不卡整体进度        |

## 核心原则

1. **学习与实现交错进行**：学完 GCN 理论 → 立刻跑 PyG Cora 示例验证；学完 Transformer → 立刻实现方案 B
2. **一次只改一件事**：每次代码改动后跑验证，确认有效再改下一件
3. **断点不过就停下来修**：不要带病进入下一阶段，宁可慢一周
4. **论文阅读要有产出**：每篇至少写 3 句话笔记 + 1 个对项目的启发
5. **因果对齐是生命线**：所有时序特征必须按滑坡日期截断，禁止数据泄漏
6. **先基线后优化**：方案 A（简单、快、稳健）→ 方案 B（加全局能力）→ 方案 C（加效率优化），逐步叠加
7. **实验记录即论文素材**：每次实验记录 AUC、超参数、耗时，最终 Master 表直接用于论文
